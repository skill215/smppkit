# smppkit v1.1.0

Optional diagnostics, active keepalive and bounded protocol utilities for the
general-purpose Go SMPP SMS library. Release notes prepared 2026-10-29; the
[release record](https://github.com/skill215/smppkit/blob/main/docs/v1.1.0-release.md) distinguishes candidate submission from
tagging and publication. This file alone does not announce a published version.

Requires **Go 1.26 or newer**. Module: `github.com/skill215/smppkit`; root package:
`smpp`. Apache-2.0, with no third-party runtime module dependencies.

After the v1.1.0 tag is published:

```sh
go get github.com/skill215/smppkit@v1.1.0
```

## Included

- **Optional structured logging:** pass `*slog.Logger` through Session config.
  Nil discards logs without consulting a global logger. Diagnostics exclude
  credentials, payloads and unchecked application error text. Handlers run
  synchronously outside Session locks and must return promptly.
- **Active enquire_link:** opt in through EnquireLinkInterval/EnquireLinkTimeout
  on Client or Server. The default interval remains zero. The shared Session
  starts scheduling after successful bind, skips local window pressure and stops
  at unbind/close. An incomplete sent exchange can retire the connection without
  retrying business requests. Bound automatic replies remain independent.
- **Raw framing and classified errors:** codec.ReadFrame/ParseHeader/WriteFrame
  expose bounded owned frame bytes and exact partial-I/O progress. DecodeError
  adds safe context while preserving errors.Is/As causes. Transport policy and
  malformed-frame handling remain explicit caller responsibilities.
- **DLR helpers:** message.ParseReceipt/BuildReceipt retain separate text/TLV
  evidence, opaque IDs, missing fields, duplicates and conflicts. Select text
  interpretation and output format explicitly. Construction returns existing
  DeliverSM/DataSM bodies using caller-provided facts and standard validation.
- **UDH national-language protection:** high-level text operations reject
  unsupported language-table declarations before invoking a text codec. Incoming
  raw evidence is retained; requested decoding reports its unsupported status.
  This is protection against silent misdecoding, not a national-language codec.

Examples cover standard slog integration, raw framing, receipt construction and
parsing, and optional Client/Server heartbeat configuration. Independent wire
fixtures, boundary/concurrency tests and allocation benchmarks accompany the
features.

## Compatibility and corrections

The six existing public packages, concrete PDUs, versioned Codec and shared
Session remain. Public additions follow the v1 keyed-struct-literal policy;
existing extension interfaces acquire no required methods. Decode errors now
have an outer wrapper; inspect errors with errors.Is/As rather than concrete
outer-type assertions or string parsing. Go remains 1.26.

Pre-release S5 corrections prevent a completed heartbeat exchange from closing
a healthy connection merely because its deadline is also observable. Enquiries
crossing unbind are consumed without replies while Unbinding; business admission
remains closed. Bound automatic replies are unchanged. Formal regressions cover
the corrected races, and the receipt support matrix has been reconciled.

## Boundaries

SMPP 3.3 remains TLV-free; 3.4/5.0 retain standard/customer TLVs within the support
matrix. DLR text syntax, default alphabet choices and legacy 3.3 marker behavior
are explicit peer conventions, not universal SMSC formats. Unknown or conflicting
report evidence is not resolved into a final delivery verdict. Submission
acceptance, report content and report ACK remain separate observations.

No persistence, durable ACK, delivery tracking/aggregation, routing, automatic
reconnect, uncertain-request retry, broadcast support or general national-language
codec is added. External SMSC interoperability is not newly claimed. Existing
bounded multipart and per-segment result behavior remains unchanged.

## Validation and provenance

Local Go 1.26.10 build, vet and full race checks passed. Corrected heartbeat and
lifecycle tests passed 20 race-enabled repetitions at each of CPU settings
1, 2 and 4. Feature-specific records include timed fuzz runs, independent byte
samples, executable examples and allocation benchmarks with their measured
scope. A sandbox-only TCP-listener failure is recorded separately from the
successful permission-enabled run. Exact copy counts and universal performance
improvements are not claimed.

Remote CI must pass on the actual submitted revision; local results are not
GitHub Actions results. The existing publication workflow checks matching main
and tag commits and appends verified commit/CI links when publication occurs.
No tag or formal release is authorized by candidate preparation.
