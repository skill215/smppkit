# v1.2.0 prerelease review

Reviewed: 2026-11-06 (Asia/Shanghai). **Local review complete; no actionable
release-blocking code findings identified.** F1/F2 remain uncommitted and
unreleased. The working tree was preserved. This review changes documentation
and evidence only; it does not fix, extend or refactor production code.

Subsequent release preparation is tracked in the [publication checkpoint](v1.2.0-release.md).
The findings and missing-note observation below describe the review-time state.

## Release judgment

The implementation can enter release preparation. It is **not ready for an
immediate tag/publication**: `docs/releases/v1.2.0.md` is not yet present, and no
submitted v1.2.0 candidate has remote CI evidence. The release workflow explicitly
requires the version-specific notes file and successful CI for the exact commit.
Those are remaining publication tasks, not new library feature requirements.

No RV26+ defect number is assigned without a concrete reproducible defect.
No new permanent regression tests were added: existing tests cover the checked
contracts, and the additional exploratory sweeps found no failing input to
promote. This does not claim that the implementation is defect-free.

## Scope and findings

| Area | Review result |
| --- | --- |
| F1 field/rule identity | Checked the catalog against validation sites, indexed destinations/TLVs, absent SAR tags, historical FieldError cases and deliberate exclusions. No concrete mismatch found. |
| F1 error compatibility | Existing sentinel membership and DecodeError classifications are preserved in the checked paths. Customer TLV causes are intentionally newly inspectable, beneath the safe outer summaries. |
| F2 DCS and splitting | Checked the 3.3/3.4/5.0 whitelist, single/multipart transitions, UDH8/UDH16/SAR/Payload sizes, ports, empty input and 255-part limits. No boundary violation found. |
| F2 ownership/resources | Data and metadata snapshots, independent outputs and accounted-output limits match the documented contract. MaxOutputBytes is not an exact heap cap or a substitute for Codec.MaxFrame. |
| Reference management | Text/binary share the same allocator and sendPlan. Full preflight precedes reservation/write. Single-part plans consume no lease; failures and positive responses do not release leases early. Existing shared-domain and concurrency tests pass. |
| Public API | New types/alias/entry points are additive. Existing type/function declarations and exported struct/interface shapes match the v1.1 baseline. The development snapshot matches current go doc output. |
| Scope/architecture | Go 1.26 remains the minimum. No new runtime dependency, persistence, delivery engine, retry policy, protocol stack or negotiation exception was introduced. |

Reference retention remains the existing first-Reserve-based deadline, with no
automatic renewal. Applications must choose a retention period that covers local
queueing/sending and the peer's reassembly/retransmission horizon. This review does
not reinterpret a reference lease as an indefinitely pinned active-send handle.
Similarly, the explicit binary DCS whitelist is a high-level policy, not a change
to raw Codec support. Ordinary submission acceptance remains distinct from final
delivery and memory admission remains the automatic ACK boundary.
