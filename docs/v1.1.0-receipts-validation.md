## Implementation and review

`message.ParseReceipt` extracts bounded owned evidence with explicit version and
text dialect. It separates text and standard TLVs, keeps report kind distinct
from state, and diagnoses absent, duplicate, malformed, unsupported or conflicting
fields without selecting a winner. It is not a replacement for strict Codec
validation. Unsupported direct 3.3 TLVs remain raw and are never interpreted.

`message.BuildReceipt` requires explicit version/command/format and caller-provided
report facts. It returns existing concrete DeliverSM/DataSM and reuses Codec
preflight, including data_sm delivery-direction checks. It has no Session, ACK,
persistence, routing, business status mapping or delivery-tracking behavior.
The [receipt contract](receipts.md) separates protocol rules and gateway conventions.

Review covered bounds before allocation, fixed grammar/token work, safe diagnostic
fields, ownership of raw/parsed evidence, duplicate ambiguity, distinct text/network
error namespaces, explicit encodings, lack of timestamp/ID normalization, version
restrictions, constructor output ownership and absence of partial output on error.
Final review also removed a text-token restriction from TLV-only ID construction:
legal non-NUL ASCII IDs retain their protocol values, including spaces/colons and
control octets. A regression verifies preservation. The full build/vet/race and
fuzz checks were rerun after that correction. No private gateway code/data is
copied. No external encoding dependency is added.

The public API stays in the existing message package, without new extension
interfaces or mutable registries. Its constructor uses codec as the existing
protocol-validation layer; codec does not depend on message. The six-package
development API snapshot was regenerated; the historical v1.0 snapshot and
Go 1.26 module declaration remain unchanged. The
[source manifest](validation/v1.1.0-receipts-source.sha256) identifies all project
Go sources and go.mod at this validation state, including earlier local increments.

## Independent and boundary coverage

Ten profile/format cases use complete [literal wire PDUs](wire-samples.md#v110-receipt-fixtures)
for text, TLV, mixed, intermediate and payload carriers. Constructor output is
compared to those literals; parser assertions use decoded literal inputs and
independently authored typed evidence, not only helper round trips.

Additional tests cover opaque/leading-zero IDs, omitted counts, ten-digit dates,
invalid date precision/components, terminal text with label-like content,
unknown status text/numeric states/network types, malformed lengths/C-octets,
duplicate ID/state/payload values, carrier and text/TLV conflicts, disjoint error
namespaces, ownership, explicit/raw dialects, unsupported DCS/UDH, malformed GSM7
and UCS2, and version-specific state/type ranges. Fixed raw budgets, TLV counts
and token limits have exact-limit and over-limit cases. Unknown syntax consumes
the same bounded token budget as recognized fields.

Constructor tests reject invalid options, forbidden 3.3 forms, invalid state,
field injection, unsupported text state spellings, invalid addresses, oversized
legacy reports and incompatible supplied evidence that would otherwise be lost.
Legacy GSM7 underscore bytes are asserted separately. Concurrent helper calls
share immutable inputs under race. Example tests cover both concrete report types
and all supported versions, with explicit ACKs and joined cleanup.

## Limits

The selected text grammar is a documented peer convention, not every SMSC dialect.
It accepts ASCII grammar after explicitly supported decoding; packed GSM, national
language UDH, other default alphabets and arbitrary vendor syntax remain raw or
produce diagnostics. Text-only 5.0 is explicitly a compatibility format and its
missing standard ID/state TLVs are diagnosed. Unknown/partial evidence does not
establish successful or final delivery. No external carrier conformance or
long-running delivery-system behavior is claimed. Benchmarks exclude networking
and do not instrument exact memory-copy counts.
