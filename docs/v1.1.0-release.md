# v1.1.0 candidate submission and publication gates

Prepared 2026-10-29 (Asia/Shanghai). **Release candidate; not tagged or published.**
The maintainer has authorized preparing the release notes, finalizing candidate
documentation, committing/pushing the implementation and checking its CI.
Tag creation and formal publication are explicitly excluded from this step.
The latest published version remains v1.0.0; no v1.1.0 release date is assigned.

## Candidate contents

S0–S5 are complete locally: optional slog diagnostics, UDH national-language
protection, bounded raw framing/classified errors, opt-in shared Session
heartbeats, and stateless DLR helpers. RV22–RV24 have formal regressions and
corrected contracts; the [S5 recheck](v1.1.0-s5-recheck.md) found no remaining
local correctness blocker in those corrections.

The [release notes](releases/v1.1.0.md), [changelog](../CHANGELOG.md),
[README](../README.md), [support matrix](support.md) and [roadmap](roadmap/v1.1.0.md)
describe that candidate without announcing publication. The
[v1.1.0 API snapshot](api-v1.1.0.txt) is preserved separately from the v1.0
baseline. Go remains `1.26.0`; the existing CI 1.27.x job is additional compiler
coverage, not a minimum-version upgrade. Apache-2.0 and AI disclosure remain.

The initial candidate submission included release documentation and the
previously uncommitted S0–S5 implementation and evidence. The subsequent
[CI correction](v1.1.0-ci-fuzz.md) changes fuzz budgets and failure evidence
retention without altering reviewed Go sources or adding library functionality.
All public files, including new sources/examples/tests, must be included; `/doc/` stays
ignored and reference repositories remain read-only.

## Validation identity

The S5 correction manifest and stage reports identify the previously tested
implementation. Candidate documentation updates intentionally supersede some
document hashes in those historical manifests; Go sources and go.mod remain
unchanged. [Submission checks](validation/v1.1.0-candidate-checks.txt) record the
current packaging, source/API, formatting, build/vet and local race checks.

Actual commit and GitHub Actions run identities are determined after commit/push,
and must be checked together. Successful local checks are not evidence that a
remote workflow passed. Submission completion is reported with the exact pushed
commit and its Go workflow URL; this preparation record does not predeclare a
remote result or a publication result.

The initial candidate `e1083a02245f2d09a0aad48b7f3076437f82d0be`
[failed its first CI attempt](https://github.com/skill215/smppkit/actions/runs/40827967811)
at Go 1.26.10 timed fuzz shutdown; the Go 1.27 job was cancelled by fail-fast.
That failure remains recorded and was not rerun. The CI correction requires a
new commit and a successful run of both complete jobs on that exact revision.

## Remaining publication steps

1. Verify the configured Go workflow on the final submitted SHA and main after
   integration: both 1.26.x and 1.27.x jobs, including all configured fuzz targets.
   Investigate failures; do not waive tests or retry an unexplained failure.
2. Obtain explicit authorization to tag and publish. Candidate commit/push
   authorization does not authorize the release tag.
3. Ensure `docs/releases/v1.1.0.md` and final version/date status match that
   publication action. Never overwrite an existing release tag.
4. Push the authorized tag only at the verified main revision. The existing
   Release workflow checks tag/main identity, waits for successful main and tag
   Go CI on the same SHA, then creates the GitHub Release with verified links.

No tag or Release is created as part of the present candidate submission. No
persistence, delivery engine or external interconnection requirement is added.
