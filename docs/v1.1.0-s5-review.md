## RV22 — P2: completed heartbeat exchange can retire a healthy Session

Locations: `session.go:418–422` (the writer join select) and
`session_heartbeat.go:72–78` (`cancelHeartbeatWrite`).

A successful correlated response can already be published, and its complete
request write can already have returned, before the requesting goroutine resumes.
If the probe deadline expires before that goroutine reaches the join select,
both `j.done` and `ctx.Done()` are ready. Choosing the latter invokes
`cancelHeartbeatWrite`, which closes a bound Session with `ErrEnquireLinkTimeout`
without checking whether the exchange is already complete. The same request
then returns `ResponseReceived`, all 16 bytes written, and nil error.

This is a false connection retirement, not a missing response or stalled writer.
Outstanding business operations can become uncertain as a consequence. It is
conditional on automatic probes and completion/deadline scheduling; the default
disabled scheduler is not affected by this path.

`TestS5CompletedProbeDeadline` joins a real net.Pipe request write, publishes an
independently decoded literal response under the same mutex as dispatchResponse,
then makes the deadline observable before allowing request cleanup to resume.
This intentionally controls the internal publication point; it does not claim
to exercise the reader dispatch in that test. Three race-enabled runs produced
15/32, 13/32 and 18/32 false retirements for automatic probes. The otherwise
identical ordinary Request controls had zero false retirements in all three runs.
Those counts demonstrate the select race, not an estimated production frequency.

Correction scope: distinguish an already completed write with a correlated
response from an incomplete exchange before applying timeout retirement. Keep
the existing timeout for a fully written probe with no response, and for a
response received while Write is still stalled. Reuse the existing no-response,
response-before-write-completion and unbind deadline tests when fixing it.

## RV23 — P2: an in-flight heartbeat crossing unbind aborts graceful shutdown

Locations: `session.go:224–228` (Unbinding inbound eligibility) and
`session_reader.go:139–155` (control-request dispatch).

An endpoint can admit its local unbind while the other endpoint's automatic
enquire_link frame is already in flight. On receiving unbind, the probing peer
stops scheduling and lets its started frame finish before writing unbind_resp,
as required by the current keepalive contract. The initiating endpoint, however,
rejects that pre-existing enquiry in Unbinding, returns ErrState from the reader
and closes before a successful unbind exchange. A healthy pair of Sessions can
therefore fail Shutdown solely because the scheduled probe crossed shutdown.

`TestS5HeartbeatCrossesUnbind` uses two real bound Sessions and a gated read to
hold the already started enquiry until the other direction's unbind is admitted.
Both client-initiated and server-initiated shutdown fail in 3.3, 3.4 and 5.0;
all six cases fail in each of three race-enabled repetitions. Both runtimes are
closed and joined. The private bound constructor isolates lifecycle behavior;
this is not another bind-negotiation or protocol-conformance proof.

Existing `TestHeartbeatRemoteUnbindDuringBlockedWrite` verifies that the sending
side finishes its frame using a raw byte peer, but that peer accepts the frame.
It does not expose the receiving Session's eligibility mismatch. The added
paired-runtime probe fills this specific coverage gap; existing independent byte
fixtures remain the protocol evidence.

Correction scope: define and handle incoming control traffic already in flight
during unbinding without turning this valid crossing into a terminal state error.
Preserve bounded serialized writes, shutdown deadlines and stopped scheduling;
do not reopen business admission or start new probes. Keep coverage for both
endpoints, all three profiles, crossed unbind and stalled writes.

## RV24 — P3: the support matrix contradicts implemented receipt parsing

Location: `docs/support.md:139–141`. The Receipts row advertises optional v1.1.0
text/TLV parsing and construction, but the following combined “Receipt text
dialects / tracking / aggregation” row says “Not implemented”. This conflicts
with ReceiptKeyValue, the public receipt contract and the implemented examples.

Separate the implemented explicit dialect from unsupported arbitrary vendor
dialects, tracking and aggregation. Reconcile the older blanket scope wording
in `docs/compatibility.md` at the same time. Also clarify that the combined
unbind/enquire_link command row's optional scheduling applies only to enquiry.
These are documentation corrections, not requests for more receipt features.

## Public contract and DLR audit

- All six public packages match `docs/api-v1.1.0.txt` exactly. Comparison against
  the preserved v1.0 snapshot found additive declarations/configuration fields;
  named Request results do not change its Go function type. No required methods
  were added to the existing extension interfaces. Keyed exported struct literals
  remain the documented compatibility contract.
- Defaults remain silent logging and disabled active heartbeats. ReadTimeout and
  WriteTimeout retain independent meanings. Automatic bound enquiry responses
  predate this release. RV22/RV23 qualify the new lifecycle claims; passing older
  tests does not establish their correctness.
- DLR parsing requires an explicit receipt marker and version; text parsing is
  opt-in. Text/TLV sources stay separate, duplicates do not silently choose a
  winner, and malformed/unknown evidence remains diagnostic. Raw input, parsed
  values, partial evidence and safe diagnostics have distinct contracts.
- Existing tests cover literal wire frames, all allowed profile/format pairs,
  exact and exceeded byte/TLV/token limits, owned output, malformed encodings,
  UDH protection, unsupported state spellings, opaque IDs and network errors.
  Constructor output is compared to independent bytes, not only same-Codec
  round trips. No additional DLR implementation blocker was found in this review.
- 3.3 remains TLV-free on the wire. Diagnostic preservation of manually supplied
  unsupported typed fields does not relax Codec validation. Legacy 3.3 receipt
  text/marker behavior and the chosen Appendix-B-inspired grammar are explicitly
  peer conventions. Parsing a report does not establish its truth or finality.
- No persistence, delivery engine, automatic retries/reconnection, external
  interconnection requirement, Go upgrade or private logger dependency is added
  to the release gates. Broadcast and general national-language codecs stay out
  of scope. BuildReceipt's codec dependency preserves the existing layer boundary.

## RV22–RV24 corrections

Corrected on 2026-10-29, Go 1.26.10, with the existing shared Session and versioned
Codec. RV22 now supplies the correlation result to heartbeat cancellation and
checks writer completion before timeout retirement for a received response.
Without a response, a finished write still times out; with a response, a stalled
write still times out. Ordinary request cancellation is unchanged.

RV23 allows valid incoming enquiries to be consumed while Unbinding and ignores
them before response enqueueing. This explicit shutdown policy avoids an ACK
write competing with the final unbind exchange. It neither reopens business
admission nor restarts scheduling, and does not extend unbind/write deadlines.
Bound automatic responses and crossed-unbind ACK obligations remain intact.

The original probes are promoted to `session_heartbeat_regression_test.go` as
TestHeartbeatCompletedProbeDeadline and TestHeartbeatCrossesUnbind. They failed
against the pre-fix implementation and pass after correction. An additional
TestHeartbeatUnbindingDrainsEnquiries uses independent byte peers in all three
profiles to check bound automatic replies, absence of replies/new probes during
unbind, outbound enquiry rejection, successful unbind completion and continued
rejection of incoming business requests. The paired-runtime crossing test still
covers both endpoint directions. Existing blocked-write, no-response timeout,
window pressure and crossed-unbind tests are reused, not duplicated.

RV24 separates the supported explicit receipt dialect from unsupported arbitrary
vendor dialects and delivery tracking/aggregation. The compatibility scope,
keepalive/lifecycle contracts, design and changelog now match the implementation;
the matrix explicitly limits active scheduling to enquire_link. Public signatures
and the six-package development API snapshot are unchanged. No additional DLR,
persistence, delivery engine, reference-repository edit or Go upgrade is included.
