## Remaining work and next implementation steps

M0 contracts and the initial M1 codec foundation exist. Working M2 client/server
and M3 memory-messaging slices are integrated and tested. The overall design is
**not complete**, and these results do not mark all M1–M4 release gates complete.

Updated 2026-10-28; the [Release 1.0 target](release-1.0.md) is the current scope
and gate list, superseding earlier future-work descriptions in this log.

R1 is complete: [RV17–RV19](review-gaps.md#r1-corrections-and-validation) have
corrections and ordinary regression tests.

1. Audit and freeze the public SMS API and advertised command/version contracts;
   strengthen boundary tests and compile/run the examples.
2. Validate the candidate using build, vet, race, all fuzz targets, independent
   local byte peers, the local resource workload, benchmarks and the optional
   legacy simulator. Existing consumer references are not passing acceptance.
3. Keep historical commands, peer-specific 3.3 multipart, additional encodings,
   receipt dialect parsing/aggregation and 5.0 broadcast explicit as later work.
   External SMSC/consumer interoperability remains deferred by owner request.

Persistence, durable admission/ACK and application crash recovery were removed
from library scope by the owner. They are not pending implementation or release
gates. The library does not replace an SMSC/backend.

The preview uses strict standard 3.3 submission, so high-level multipart 3.3 is
not currently available. Packed GSM, national language tables, automatic
reconnect/retry and final-delivery tracking are
not implemented. Memory ACK may lose accepted content on process failure.
There is no claim of atomic multipart submission or exactly-once delivery.
