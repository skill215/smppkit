# v1.1.0 design

Date: 2026-10-29 (Asia/Shanghai). Approved local implementation scope; not a
release announcement. Go remains 1.26 (`go 1.26.0`). Keep concrete PDU structs,
immutable versioned Codec and shared Session. No new third-party dependency is
required by this design. See the [increment roadmap](roadmap/v1.1.0.md).

## Existing contracts

Logging is already implemented locally under the [logging contract](logging.md).
Keep default discard and application-owned synchronous slog handlers. Incoming
enquire_link already receives automatic responses. Opt-in active scheduling is
now implemented for issue #2, reusing writer/correlation/window machinery.
Neither feature changes submission uncertainty, ACK semantics or retry policy.

## U1: national-language declarations and text safety

UDH IE 0x24 (national-language single shift) and 0x25 (locking shift) can change
GSM7 interpretation. The existing textcodec.Encoding interface receives no UDH;
selecting a decoder by DCS alone can silently return incorrect text. An independent
sample `03 25 01 01 0b` declares the Turkish locking table: 0x0b denotes G-breve,
whereas the default alphabet decoder produces O-stroke. The normative references
are [TS 23.038, section 6.2.1.2 and Annex A](https://www.etsi.org/deliver/etsi_ts/123000_123099/123038/16.00.00_60/ts_123038v160000p.pdf)
and [TS 23.040, section 9.2.3.24](https://www.etsi.org/deliver/etsi_ts/123000_123099/123040/16.00.00_60/ts_123040v160000p.pdf).

Add message.ErrUnsupportedNationalLanguage. Prepare rejects either IE in
AdditionalUDH before encoding/fallback. Receiver keeps structurally bounded
headers and content; when text decoding is requested, either IE prevents decoder
invocation and sets Message.DecodeError to that sentinel, with Decoded=false
and empty Text. Raw-only reception (nil Encodings) has no decode attempt/error.
Receipts already bypass text decoding and retain that behavior.

Protection deliberately covers every table value, including zero, both IE types,
custom codecs, and octet-based codecs paired with these declarations. It does not
claim to interpret table IDs or decide whether a particular DCS should ignore
an IE. Full table semantics and an explicit header-aware extension are deferred.
Unknown other IEs remain opaque. Structural length checks remain in ParseSegment;
well-framed but semantically unsupported declarations are retained for caller
inspection rather than rejected during memory admission. DecodeError does not
retract an ACK or discard assembled payload/per-segment provenance. The existing
non-concatenation-UDH consistency check still prevents mixing language declarations
across multipart segments. Raw Codec behavior is unchanged.

This is a correction within the documented unsupported national-table boundary,
not a promise of new alphabet support. No required method is added to Encoding.
Independent vectors must demonstrate safe default decoding without these IEs,
no decoder/encoder callback with them, raw ownership, multipart completion and
unchanged receipt handling. Fuzz bounded UDH parsing together with the guard.

## G1: framing without semantic or transport ownership

S2 implements codec.ReadFrame, ParseHeader, WriteFrame, FrameHeader and
DecodeError/DecodeErrorKind using the shared bounded framing primitive. The
[public framing contract](framing.md) fixes ownership, limits and error semantics;
these are local unreleased additions.

The caller supplies an explicit/default documented maximum, validated before any
body allocation. Reject lengths below 16 or above the cap after reading length;
do not drain an untrusted oversized body. Distinguish clean EOF, partial length,
partial header/body and invalid length. Report actual consumed bytes; zero-filled
allocation tails must never be exposed as received evidence. A successful result
owns exactly one frame, including all 16 header bytes, and is independent of the
reader and subsequent reads. Describe mutation and sharing explicitly.

Header extraction reports raw numeric fields without declaring their semantic
validity. Reading a complete frame does not validate the body. Callers may use
strict Codec.Decode or apply their own forwarding policy. Unchanged raw frames
must retain byte identity, including unknown commands/TLVs and their ordering.
An explicit typed modification is valid only if strict decoding and re-encoding
succeed; no fallback splices arbitrary field offsets or bypasses standard checks.

WriteFrame returns actual progress and preserves transport error identity;
short/zero-progress writes cannot become success. Callers serialize writes and
own deadlines/closing. Partial writes do not imply safe retry. Frame utilities
have no connection state, automatic ACK, sequence changes, logging requirement
or background work. Fault injection with a deliberately wrong length remains an
explicit simulator operation, not successful normal framing.

## G2: error categories and diagnostic context

Add optional error types/categories without required changes to CommandCodec or
Encoding. Preserve errors.Is for existing sentinels and transport causes and
errors.As for FieldError; error text remains diagnostic, not a machine protocol.
Built-in failures should distinguish framing, unsupported command/version,
mandatory-field structure, TLV structure/validation and semantic validation.
Extension-returned errors retain their causes without inventing unsupported
classifications or declaring arbitrary callback text safe for logs.

Represent complete header availability, validated header semantics, and complete
frame acquisition separately. Decode on a supplied byte slice cannot assert any
stream-consumption fact. Read diagnostics can report consumed bytes and whether
the declared frame was fully acquired. Complete acquisition permits the caller to
reason about the next boundary; it does not mandate continuing a bad connection.
Invalid lengths/partial reads never imply successful resynchronization.

Safe context is command/status/sequence and structural field/offset metadata,
never credentials, raw payloads or TLV values. A nonzero sequence is not proof
that replying is safe. Unknown private commands retain successful Opaque decoding;
known unsupported standard commands/versions retain ErrUnsupported. Standard
commands cannot use Opaque to evade validation. Response-opcode mismatches that
require a pending request remain Session/caller correlation errors, not facts
standalone Codec can infer. No automatic NACK, disconnect or retry policy is added.

## G3: active keepalive

Implemented locally with the [keepalive contract](keepalive.md). Config adds
EnquireLinkInterval (zero disables) and EnquireLinkTimeout (zero inherits
RequestTimeout). One optional scheduler starts after successful bind and stops
on unbinding/termination; Wait joins it. The interval restarts after completion
or skip, not on arbitrary traffic, and there is no tick backlog.

The scheduler reuses Request encoding, atomic window admission, correlation and
the single writer. Full-window and not-yet-written expiry are local pressure;
started probes that exceed their exchange budget retire the bound generation
with ErrEnquireLinkTimeout. Negative responses retain PeerError, incompatible
opcodes ErrResponse, and earlier transport/Codec causes remain intact. Unbind
admission and heartbeat retirement are serialized. An active probe frame may
finish under WriteTimeout during unbinding so the shared stream is not truncated.
The receiving Session consumes enquiries crossing unbind without queuing replies;
business admission remains closed. A completed write plus a correlated response
wins over a simultaneously observable probe deadline; an incomplete exchange
retains the existing deadline policy.
ReadTimeout/WriteTimeout are independent; neither is silently increased.

No reconnect, request replay, idle-traffic inference or reserved control window
is added. Business byte/outcome evidence remains unchanged. See the
[local validation](v1.1.0-keepalive-validation.md).

## G4: delivery-receipt parsing and construction

G4 is approved for v1.1.0 and includes bounded stateless parsing and pure
construction helpers. It uses existing DeliverSM/DataSM PDUs and Session, not a
new receipt transport or delivery engine. S4 now implements ParseReceipt and
BuildReceipt in message, with the explicit [receipt contract](receipts.md) and
[local validation](v1.1.0-receipts-validation.md). They are opt-in and do not alter
existing receiver classification or Session ACK behavior. The named key/value
dialect is Appendix-B-inspired; its exact bounds and accepted encodings are
documented separately from standard TLV rules. G1/G2 historical evidence does
not claim this later implementation.

### Standard behavior

- [SMPP 3.3 section 6.3.5](https://smpp.org/SMPP-v3.3.pdf#page=24) describes
  deliver_sm receipts identified by esm_class with information in message text;
  detailed formatting is delegated to its Applications Guide. No TLVs in 3.3.
- [SMPP 3.4 sections 4.6, 5.2.12 and Appendix B](https://smpp.org/SMPP_v3_4_Issue1_2.pdf#page=167)
  cover deliver_sm/data_sm receipts. Appendix B gives a vendor-specific text
  example, not a universal mandatory layout. Its ten-digit YYMMDDhhmm dates
  are distinct from query_sm_resp.final_date. Counts sub/dlvrd need not exist in
  every dialect; missing values must not be invented.
- [SMPP 5.0 sections 4.3.5.1–2](https://smpp.org/SMPP_v5.pdf#page=90) distinguish
  MC receipts from intermediate notifications and describe addresses, esm_class
  and receipt TLVs. The parser must retain the notification kind rather than
  inferring finality from the existing broad Receipt boolean.
- Standard network_error_code is a network type plus a two-octet error code
  ([5.0 section 4.8.4.42](https://smpp.org/SMPP_v5.pdf#page=157)). It is not a
  universal status-byte/error-byte pair; its value need not equal text err.

### Parsing contract

Accept explicit supported text dialects from deliver_sm.short_message or
message_payload (including data_sm), and extract standard receipt TLVs. Retain
text fields, TLV fields and raw bytes separately without implicit precedence.
A missing sub/dlvrd/text can be diagnosed while returning available ID/state
information; no synthesized counts. Detect duplicate, malformed and conflicting
fields with bounded input/work. Compare only evidence with the same semantics:
ID/state conflicts differ from unrelated text err and network_error_code values.

Preserve opaque identifiers, leading zeros, raw status/error and timestamp strings;
do not guess numeric radix, time zone, century or absent precision. Unknown states
and unsupported dialect content remain observable. Ordinary content is not made
into a receipt just because it contains id: or stat:. Diagnostic strings exclude
message content. No mandatory change to strict Codec acceptance is implied.

### Construction contract

Given explicit caller-provided message identity, report kind, state, addresses
and optional error/time/text information, construct owned existing typed PDUs
for an explicit protocol version/format. Validate limits before producing output;
do not silently truncate, infer delivery or populate unsupported TLVs in 3.3.
The caller uses Session.Request or standalone Codec to transmit. Sequence
allocation, response correlation and ACK use their existing contracts. Construction
alone owns no timers, connection, store or ID-to-submission association.

Submission responses, later report content and report-response ACKs are distinct
outcomes. A server example may explicitly simulate a result, but the library must
never generate DELIVRD merely because submission was accepted. Actual delivery
outcomes come from the application. Receipt processing never aggregates parts,
routes reports, invokes HTTP callbacks, caches data or supplies persistence/retry.

### Gateway boundary and validation

Gateway internal-protocol status mapping, message-ID generation/radix conversion,
address normalization and proprietary error layouts stay in adapters. Their
presence is not a new universal SMPP rule. Generic parser options may cover
omitted counts and supported text variants; no gateway-private interface or data
is imported. Raw unsupported fields remain available to applications.

Use independently authored synthetic bytes for text-only/TLV-only/mixed receipts,
missing counts, ten-digit dates, opaque IDs, unknown states, source conflicts,
network error structure and intermediate notifications. Test construction and
parsing against independent bytes, not solely against each other. Add bounded
fuzzing, allocation benchmarks and compiling Server/Client receipt examples.

## Compatibility and release evidence

No speculative peer relaxation is added. Codec already accepts the checked empty-
destination receipt sample; an endpoint migration must test role, negotiated TLVs
and explicit ACK separately. Private captured traffic must not enter public tests;
construct synthetic independent equivalents. Existing bind C-octet limits include
NUL, and 12-digit local query final dates apply only to the existing 3.3/3.4 rules.
No broadening of these rules is part of this release.

Keep prior logging changes and historical v1.0 API records. Document new APIs and
corrections separately; update support claims only after implementation. Validate
each increment with relevant regressions, build/vet/race and targeted fuzz and
allocation/copy benchmarks. New evidence identifies the source state and toolchain;
old consumer/simulator runs do not prove new Session behavior. Complete library
release review separately from any consumer migration or external interconnection.
