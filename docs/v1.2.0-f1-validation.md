# v1.2.0 F1 local implementation and validation

Date: 2026-11-06 (Asia/Shanghai). **Unreleased, uncommitted local work.** F1 is
implemented; F2 binary helpers are still planned. This is not a publication or
external interoperability record. Go remains 1.26 (`go 1.26.0` in go.mod).

## Implementation and contract decisions

- Finalized the [semantic field/rule catalog](semantic-diagnostics.md): two new
  public types, 16 rule constants, and inspectable field, index and TLV metadata.
  Identifier strings are separate from error prose and input values.
- Integrated existing header, address, message, submit_multi, standard/customer
  TLV and data_sm contextual checks. Existing scalar/value acceptance predicates
  and shared Codec/Session architecture are retained; no second validator added.
- Preserved ErrValidation/ErrUnsupported and all four historical semantic
  FieldError decode cases, including their exact locations and DecodeMandatory
  classification. Optional-section failures remain DecodeTLV.
- Retained previously discarded customer validator causes alongside ErrValidation,
  without formatting them in safe summaries. Private command causes remain intact.
- Finalized the separate [binary DCS policy](binary-dcs.md): 3.3 `0x04`, 3.4/5.0
  `0x02` and `0x04`. This whitelist is for future high-level helpers; raw Codec
  acceptance has not been narrowed and F2 is not claimed as implemented.

The [development API snapshot](api-v1.2.0.txt) was generated using Go 1.26.10
`go doc -all` for all six public packages. No prior type/function declaration
line was removed or changed compared with api-v1.1.0.txt. Source review confirms
no existing exported struct fields or required interface methods changed.
The snapshot check is evidence, not an automated compatibility proof.

## Regression evidence

[Semantic tests](../codec/semantic_error_test.go) cover independent invalid TON,
NPI, flags, DCS, TLV length/value/cardinality/applicability/dependency samples;
repeated destination indices; source-error stickiness; time vs structural errors;
header/status checks; contextual direction/mode failures; customer callback causes
and safe summaries; and concurrent errors on one shared Codec. Existing tests
continue to exercise valid boundaries and normal wire behavior.

Historical FieldError tests assert field, offset, reason and sentinel membership,
not just non-nil errors. Customer callbacks are checked for version/command/width/
cardinality admission and cause preservation, including ErrUnsupported and
FieldError causes without changing DecodeTLV. Independent [wire samples](wire-samples.md#v120-semantic-diagnostic-samples-unreleased)
are not generated through Append. FuzzDecode now seeds those samples and checks
diagnostic metadata invariants in addition to existing round-trip/ownership checks.

Raw records: [checks](validation/v1.2.0-f1-checks.txt),
[fuzz](validation/v1.2.0-f1-fuzz.txt), and
[benchmarks](benchmarks/semantic-go1.26.10-linux-amd64.txt).

Native fuzz targets were FuzzDecode, FuzzEncodeSM, FuzzSubmitMulti,
FuzzStandardTLVSection, FuzzSemanticTimes, FuzzDataDirection, FuzzDataResponse and
FuzzRawFrame. Each used Go 1.26's existing execution-budget policy with an
external 600-second wall cap; all completed normally, without retries or ignored
failures. The other packages' fuzz seeds ran in the full race suite; no new native
message/charset campaign is claimed for this Codec-only change.

The initial sandbox run could not write the default cache, then full ordinary
tests were blocked from opening loopback TCP sockets. Writable caches and an
authorized local test process with socket access resolved those environmental
restrictions; the full race suite included the affected TCP/TLS regressions.
No tests were skipped and no external SMSC was contacted.

## Measurements and limits

Nine new benchmark cases isolate successful/failed encoding and decoding,
contextual checks, errors.AsType inspection and error formatting. The existing
33 Codec cases were also rerun. The [benchmark guide](benchmarks/README.md#semantic-diagnostics-v120-development)
records all nine diagnostic medians and scope. ContextValid and InspectAsType
measured 0 B/op and 0 allocs/op; constructing a contextual failure measured
64 B/op and one allocation. Full codec paths still allocate owned results and
intermediate buffers. B/op is not a copy counter or a retained-memory bound.

No code from reference libraries was copied, no reference checkout was edited,
and /doc/ remains ignored. No remote CI, commit, push, tag, release or production
interconnection was performed. F2 API/policy materialization and binary sending
are the next implementation stage; this F1 result does not certify that feature.
