## U1: national-language protection

- Reject language-table IE declarations in high-level text preparation before
  invoking encoders; report a stable unsupported-language error.
- Preserve structurally bounded incoming IEs and payloads. If configured text
  decoding encounters either language-table IE, report DecodeError without
  invoking the decoder or returning successful text. No configured decoder
  means raw-only delivery as before. Receipt handling remains raw.
- Do not guess table identifiers, accept fallback text under a conflicting
  declaration, or change raw Codec behavior. This conservative protection also
  applies to custom encoders and explicit default-table declarations; a future
  header-aware API can add support without changing Encoding's required methods.
- Keep the existing bounded receiver, ACK policy and multipart consistency rules.

Local evidence: [U1 validation](../v1.1.0-udh-validation.md).

## G1/G2: raw frames and actionable errors

- Separate bounded frame acquisition from strict typed decoding. Caller-owned
  transport deadlines, lifecycle and serialization remain explicit.
- Define header availability and validation separately from frame consumption;
  publish exact partial-I/O accounting and stable errors.Is/errors.As categories.
- Preserve ErrValidation, ErrUnsupported, FieldError and transport error causes.
  Unknown unregistered private commands still decode as Opaque; they are not
  reclassified as unsupported standard commands.
- Keep raw bytes unchanged unless the caller explicitly decodes and modifies a
  supported PDU. No automatic ACK, sequence allocation, stream resynchronization,
  heartbeat, or malformed-frame acceptance is implied.
- Validate maximums before allocation. Cover fragmented/coalesced input, short
  header/body, invalid lengths, malformed mandatory fields/TLVs, negative response
  bodies, byte equality and partial writes. Record B/op and allocs/op.

Implemented API/behavior: [framing and diagnostics](../framing.md).
Local evidence: [G1/G2 validation](../v1.1.0-framing-validation.md).

## G4: optional delivery-receipt parsing and construction

- Parse explicit supported text dialects and standard receipt TLVs from
  deliver_sm and data_sm, preserving each source and missing/conflicting fields.
- Treat Appendix B as an example, not a universal mandatory layout. Support
  meaningful partial results without inventing sub/dlvrd; distinguish report
  date grammar from query final_date and intermediate reports from final ones.
- Preserve opaque IDs and raw network errors; do not import gateway radix,
  status mapping or proprietary status/error-byte conventions.
- Add pure helpers producing existing typed DeliverSM/DataSM with caller-supplied
  outcomes, explicit version/format and bounded owned output. No automatic DLR
  on submit success. No TLVs in 3.3; reuse existing Codec and Session for I/O.
- Keep parsing/construction independent of ACK, persistence, routing, callbacks,
  caches and multipart delivery aggregation. Exact contracts and normative
  references are in the [G4 design](../v1.1.0-design.md#g4-delivery-receipt-parsing-and-construction).
- Validate independent bytes, source conflicts, missing/invalid fields, limits,
  fuzzing, allocation benchmarks and runnable Server/Client examples in S4.

Contract: [receipt helpers](../receipts.md). Execution evidence: [G4 validation](../v1.1.0-receipts-validation.md).

## Optional structured logging with default discard

### Problem

The library has no injectable diagnostic logger. In particular, per-connection
handshake failures handled inside `Server.Serve` are not visible through its
return value.

### Proposed scope

- Add optional structured logging through session configuration, also usable
  for Client/Server setup diagnostics.
- Use `*slog.Logger` with application-owned `slog.Handler` adapters. See the
  finalized [logging contract](../logging.md).
- A nil logger means discard. Do not use the global default logger or require
  a third-party logging backend.
- Cover handshake failures, protocol/transport failures, heartbeat failures,
  and bounded-resource exhaustion. Use suitable levels for normal lifecycle
  and control-command metadata.
- Do not log credentials, message contents, raw PDUs, arbitrary TLV values,
  or unchecked application-provided error text.
- Keep returned errors and `Session.Err` as the primary outcome API.
- Invoke handlers outside Session locks. Document concurrent, prompt handler
  behavior. Do not add an unbounded asynchronous logging queue.
- Keep standalone Codec operation free of mandatory logging.

### Acceptance criteria

- [x] Document public configuration and the default-discard contract.
- [x] Test silence by default, explicit injection, safe fields, levels, and
      concurrency.
- [x] Provide a compiling generic handler integration example without private
      application dependencies or code.
- [x] Benchmark disabled/enabled logging overhead, including B/op and allocs/op.
- [x] Run build, vet, race tests, and applicable benchmarks; record actual results.

Local execution evidence: [logging validation](../v1.1.0-logging-validation.md).

## Opt-in Session enquire_link scheduling

### Current behavior

Bound Client and Server sessions already automatically answer incoming
`enquire_link` through the shared serialized writer, preserving the request
sequence. This does not require an application `Receive` loop. Active periodic
enquiry is opt-in in v1.1.0; see the [contract](../keepalive.md).
The default `ReadTimeout` remains two minutes.

### Proposed scope

- Add opt-in periodic initiation to shared Session configuration, usable by
  both Client and Server.
- A zero interval disables active enquiry to preserve existing behavior.
  Automatic replies remain enabled independently.
- Start after successful bind, stop on unbinding/termination, and join runtime
  work through `Wait`.
- Allow at most one automatic probe in flight, do not accumulate ticks, and
  reuse protocol validation, correlation, and the serialized writer.
- Specify interval/response-timeout defaults and interaction with
  `RequestTimeout` and `ReadTimeout`.
- Distinguish local admission/window pressure from transport failure or missing
  peer response. Skip/defer a probe when there is no window capacity, using
  atomic admission.
- Require the expected correlated response. Define unsuccessful replies and
  sent-probe timeout outcomes explicitly.
- Retire an unresponsive session with an explicit cause. Preserve uncertain
  outcomes for outstanding business requests.

### Acceptance criteria

- [x] Document configuration, defaults, lifecycle, and failure contracts.
- [x] Test disabled defaults, post-bind start, one in-flight probe, exact
      response correlation, timeout/error cases, full windows, and shutdown
      races.
- [x] Reuse independent wire samples and automatic-response tests across SMPP
      3.3/3.4/5.0; add only missing coverage.
- [x] Update Client/Server examples to distinguish explicit initiation from
      existing automatic replies and explain the `ReadTimeout` interaction.
- [x] Run build, vet, race, and applicable fuzz/benchmark checks; record actual
      results.

Local evidence: [heartbeat validation](../v1.1.0-keepalive-validation.md).
