# v1.2.0 F2 local implementation and validation

Date: 2026-11-06 (Asia/Shanghai). **Unreleased, uncommitted local work.**
F1 and F2 are implemented locally; overall release review and remote candidate CI
remain pending. This record covers F2 and regressions of shared code, not a
publication or external SMSC interoperability claim. Go remains 1.26
(`go 1.26.0` in go.mod), with no new runtime dependencies.

## Implemented contract and review

- Added `message.Binary`, `BinaryPolicy`, `PrepareBytes`, the root BinaryMessage
  alias and Session.SendBinary. Byte plans reuse immutable Plan and Materialize;
  the encoding label is `binary`, with no character conversion or string input.
- Followed the finalized DCS table: 3.3 accepts 0x04 and single-part, header-free,
  TLV-free planning; 3.4/5.0 accept 0x02/0x04 and the existing modes. Raw Codec
  acceptance and negotiated TLV admission are unchanged.
- Added input, segment and accounted-output budgets before Data/TLV copying.
  MaxOutputBytes counts repeated metadata and generated headers/TLVs rather
  than borrowing the text-only MaxEncodedBytes name. The exact accounting and
  allocation exclusions are in the [binary contract](binary-messaging.md).
- Extracted private sendPlan from SendText without changing its sequence of
  preflight, role/TLV checks, reference leasing or Request calls. Both public
  senders use the same per-part results and reference domain. No public SendPlan,
  replay, reference early-release, persistence or binary-specific receiver added.
- Extracted the existing optional metadata checks into prepareOptional for both
  planners; text encoders, fallback, split boundaries and budget policy remain
  unchanged. Shared UDH validation preserves national-language protection.
- Reviewed input/Plan/output ownership, count arithmetic, metadata amplification,
  preflight-before-write/lease behavior, API additions and version restrictions.

The [API snapshot](api-v1.2.0.txt) was regenerated with Go 1.26.10 go doc -all
for the six public packages. Against the local F1 snapshot, the declaration-line
comparison found exactly five additions (the types/alias and two entry points
above) and no removals or signature changes. Source review found no changes to
existing exported struct fields or required interface methods. This is evidence,
not an automated proof of every possible source compatibility property.

## Regression evidence

[Planner tests](../message/binary_test.go) cover all 256 DCS values for each of
three versions, raw Codec acceptance, independent complete UDH8/UDH16/SAR/Payload
frames, empty/exact-fit/oversized data, 255-part limits, ports and UDH/TLV conflicts,
input/output budget boundaries, oversized/empty TLV amplification, snapshot
ownership, concurrent Plan use and reverse-order raw reconstruction.

[Session tests](../messaging_binary_test.go) cover both DCS values and all four
modes in both directions with window=1, single-part sending across all versions,
reference capacity shared between binary/text and separate Sessions, concurrent
binary sends, cancellation, role/negotiation rejection, frame limits and reference
width. A second-part validation failure verifies that all parts are preflighted
before the first write or lease; observed transport writes remain zero.

Existing peer-rejection and independent transport-fault tests now run the same
assertions for both SendText and SendBinary. They preserve accepted IDs,
ResponseReceived/NotWritten/PartlyWritten/Written/NotAttempted outcomes, exact
progress, cancellation uncertainty and stopped scheduling. The peer response
bytes and outgoing-header checks in the fault test do not use Codec serialization.
[Wire fixtures](wire-samples.md#v120-binary-message-samples-unreleased) are also
hand-authored independently of the planner/serializer.

FuzzPrepareBytes includes an independent acceptance oracle for its bounded,
metadata-free domain, not only a check of successful round trips. Successful
plans must preserve raw octets, numbering, DCS and Codec admissibility. The
existing text and UDH fuzz targets exercise the shared helpers.

## Executed checks

Environment: Go 1.26.10, linux/amd64 under WSL, AMD Ryzen 7 6800H.
GOTOOLCHAIN=local, GOPROXY=off, caches under /tmp. Full tests and executable
client/server examples used authorized loopback access; no external SMSC was
contacted. The initial focused maximum-payload test used the default Codec frame
cap and correctly failed: it was corrected to select 128 KiB explicitly when
testing the TLV maximum, while a Session regression asserts default-cap rejection.
A test-only custom TLV probe was also corrected to declare its required version
and command scope. No production check was weakened to make either fixture pass.

statistical regression comparison is inferred from these local measurements.

## Scope and next step

F2 intentionally does not add arbitrary DCS interpretation, packed GSM, language
tables, 3.3 multipart, a negotiation exception, pacing/reconnection, persistence
or a delivery system. A valid plan can still fail Codec/Session admission; a
successful ordinary submission is not final delivery. The example's binary echo
preserves payload/DCS, not application-port or customer metadata.

Next is the v1.2.0 overall release review of F1/F2, public contracts and candidate
CI gates. This stage performed no commit, push, tag or publication. Existing work
was retained; reference repositories were not edited and /doc/ remains ignored.
